# MOSS 语音助手 —— 硬件开发需求与信息汇总

> 本文件面向**硬件负责人**（或其 AI），汇总做硬件/固件必须知道的信息。
> 依据仓库现有文档整理：`README.md`、`docs/接线方案与端口定义.md`、`docs/软件接口协议.md`、`firmware/esp32c3/moss_firmware.ino`。
> **所有 GPIO 以你手上的开发板实际丝印/原理图为准，接线前用万用表核对。**

---

## 0. 一句话目标 + 最小闭环

做一个桌面语音机器人（MOSS）：**按键录音 → 电脑 ASR 识别 → DeepSeek 理解意图 → 安全打开桌面文件 → TTS 语音播报**，用于「社团嘉年华」现场演示（目标 9/9）。

```text
按键录音 → ESP32-C3 采 16kHz PCM → Wi-Fi 上传上位机
  → faster-whisper 识别 → DeepSeek 工具调用 → 打开桌面项目
  → SAPI TTS 生成 WAV → ESP32 下载 → MAX98357A 播放 → LED 恢复待机
```

**你（硬件/固件）只负责**：采音、上传 PCM、解析 JSON、下载 WAV 播放、LED/按钮状态。
**不负责**：ASR、DeepSeek、桌面路径校验、TTS 合成——这些都在电脑端上位机。

| 部件 | 型号/规格 | 作用 |
|---|---|---|
| 主控 | ESP32-C3（假设 DevKitM-1） | 采音、上传、播放、状态控制 |

## 2. GPIO 端口定义总表（唯一接线标准）

> 原则：避开 BOOT/下载/strapping/USB 引脚（GPIO0、GPIO2、GPIO18/19）。
> ESP32-C3 **只有 1 个 I2S0**，录音(RX)与播放(TX)复用同一组 BCLK/WS，仅切换数据 GPIO。

| 信号 | GPIO | 方向 | 连接对象 | 备注 |
|---|---|:--:|---|---|
| I2S BCLK | **GPIO4** | OUT | 麦克风 SCK **和** 功放 BCLK 共用 | 一根线分叉到两器件 |
| I2S WS/LRCLK | **GPIO5** | OUT | 麦克风 WS **和** 功放 LRC 共用 | 一根线分叉到两器件 |
| 麦克风数据 | **GPIO6** | IN | INMP441 SD → ESP32 | 录音数据输入 |
| 功放数据 | **GPIO7** | OUT | ESP32 → MAX98357A DIN | 播放数据输出 |
| 录音按钮 | **GPIO1** | IN | 轻触开关一端 GPIO1、另一端 GND | 内部上拉，按下 LOW |
| WS2812 灯环 | **GPIO10** | OUT | 灯环 DIN | 状态指示 |
| （备用）舵机 PWM | GPIO3 | OUT | 后续接 SG90 | 本轮可不接 |
| （备用）OLED | 预留 | — | SSD1306 | 本轮不做 |

**避免使用**：GPIO0（BOOT）、GPIO2（strapping）、GPIO8（板上用户 LED）、GPIO9（板上 BOOT 键）、GPIO18/19（USB）。

## 3. 各器件接线明细

### 3.1 INMP441 麦克风
| 麦克风脚 | 接到 |
|---|---|
| VDD | 3.3V |
| GND | GND（共地） |
| SCK/BCLK | GPIO4 |
| WS/LRCLK | GPIO5 |
| SD/DOUT | GPIO6 |
| L/R | **GND**（选左声道） |

### 3.2 MAX98357A 功放
| 功放脚 | 接到 |
|---|---|
| VIN | 5V |
| GND | GND（共地） |
| DIN | GPIO7 |
| BCLK | GPIO4 |
| LRC | GPIO5 |
| SD（使能） | **VIN**（拉高使能） |
| GAIN | 悬空或 GND |
| 输出 +/− | 直接接喇叭两线 |

### 3.3 扬声器
- 两根引线直接接功放 **+ / −**（单声道 BTL，**不需要**接 GND）。
- 不要紧贴麦克风；外壳开 1~2mm 网孔，保持距离防啸叫。

### 3.4 WS2812 灯环
| 灯环脚 | 接到 |
|---|---|
| 5V | 5V |
| GND | GND（共地） |
| DIN | GPIO10 |
| DOUT | 不接 |

### 3.5 按钮
- 4 脚开关，对角两组内部连通；用一组对角：一脚 GPIO1、一脚 GND。
- 固件 `INPUT_PULLUP`，按下拉低触发。

## 4. 供电与共地（必读）

| 电源轨 | 供电对象 |
|---|---|
| 3.3V | INMP441 VDD、ESP32 逻辑 |
| 5V（VBUS） | MAX98357A VIN、WS2812 5V |
| GND | **所有模块必须共地** |

1. **全部共地**，否则 I2S 数据异常/杂音/全零。
2. 功放/灯环**不要**从 ESP32 的 3.3V 引脚取电（电流会超）。
3. 整机建议 **5V 2A**；灯环满亮度 16 珠电流大，演示时控制亮度。
4. 逻辑阈值兜底：5V 供电时数据高阈值 ≈0.7×5V=3.5V，略高于 ESP32 的 3.3V。多数能直连；若**无声/不亮**，把功放/灯环电源降到 **3.3V**（音量/亮度略降但信号稳）。

## 5. I2S 与音频硬约束（与上位机对齐）

- **录音**：16kHz / 单声道 / 16-bit signed PCM，小端序；默认录 4 秒 = 128000 字节。
- INMP441 常见输出为左对齐 24 位，固件右移 14 位转 16 位。
- **播放**：上位机 `/tts` 返回**标准 PCM WAV**，固件当前**跳过固定 44 字节 WAV 头**后直接把数据写 I2S。→ **不要改动这个约定**；若 WAV 结构变化必须同时改固件和接口文档。
- I2S0 录音(RX)用 `I2S_CHANNEL_FMT_ONLY_LEFT`，播放(TX)用 `I2S_CHANNEL_FMT_RIGHT_LEFT`；录音/播放之间要 `i2s_driver_uninstall` 后重装切换。

## 6. 固件职责与状态灯约定

固件（`firmware/esp32c3/moss_firmware.ino`）做的事：
1. 连 Wi-Fi（`WIFI_SSID/WIFI_PASS` 填实际值）。
2. 按钮触发 → 采 4 秒 16kHz PCM。
3. `POST /api/command` 上传 PCM。
4. 解析返回 JSON，拿 `reply` + `tts_url`。
5. 下载 WAV 播放。
6. 灯环显示状态。

**状态灯颜色约定**（WS2812，RGB）：

| 状态 | 颜色(R,G,B) |
|---|---|
| 待机 | 蓝 (0,0,80) |
| 录音中 | 红 (120,0,0) |
| 思考/联网中 | 绿 (0,120,0) |
| 播放中 | 紫 (80,0,120) |
| 错误 | 橙 (120,60,0) |

**你需要在固件里填/改的**：`WIFI_SSID`、`WIFI_PASS`、`SERVER_URL`（电脑局域网固定 IP，默认 `http://192.168.1.100:8765`）。

## 7. 与电脑端（上位机）的接口契约

上位机源码在 `server/server.py`，端口 **8765**，监听局域网。双方必须同一局域网。

### 7.1 上传音频
```http
POST /api/command
Content-Type: audio/pcm; rate=16000; channels=1
<原始 PCM 二进制，128000 字节>
```

### 7.2 成功响应（JSON 三字段）
```json
{
  "recognized_text": "打开社团嘉年华",
  "reply": "已打开社团嘉年华",
  "tts_url": "http://192.168.1.100:8765/tts?text=..."
}
```
`tts_url` 是 ESP32 可访问的局域网地址（**不是** localhost）。

### 7.3 错误响应与状态码
| 状态码 | 场景 | 固件行为 |
|---|---|---|
| 200 | 成功 | 播放 `tts_url` → 回待机 |
| 400 | 录音太短 | 显示错误 → 回待机 |
| 500 | 服务/ASR/TTS 失败 | 显示错误 → 回待机 |
| 超时 | 网络/AI 超时 | 显示错误状态，**不能一直停在思考状态** |

### 7.4 下载 TTS
```http
GET /tts?text=<URL 编码文本>  →  audio/wav
```

## 8. 联调顺序（必须按序，每步通过再下一步）

1. 固定 PCM 请求验证 `/api/command` 返回 JSON；
2. 固定 JSON 验证 ESP32 能解析三字段；
3. 固定 WAV 验证 ESP32 能下载并播放；
4. 接入真实 ESP32 录音，确认 PCM 参数正确；
5. 接入 ASR，确认 `recognized_text` 正确；
6. 接入 DeepSeek 与本地关键词兜底；
7. 验证合法白名单项目可打开；
8. 验证绝对路径/路径穿越/危险指令全被拒绝；
9. 连测 30 次，记录失败原因与耗时。

## 9. 接线顺序建议 + 上电自检

**接线顺序（减少返工）**：
1. 只接电源和地 → 确认 3.3V/5V/GND；
2. 接灯环（GPIO10）→ 点亮；
3. 接按钮（GPIO1）→ 串口打印按下/松开；
4. 接功放+喇叭（GPIO7/4/5）→ 播一段 WAV；
5. 接麦克风（GPIO6/4/5）→ 串口打印 PCM 非零；
6. 最后联调全链路。

**上电自检清单**：
- [ ] 3.3V/5V/GND 正确、无短路（万用表测通断）
- [ ] WS2812 能点亮/驱动
- [ ] GPIO1 按下读到 LOW
- [ ] MAX98357A 能出声（SD 已拉高使能）
- [ ] INMP441 PCM 有波动（非全零）
- [ ] 所有模块共地、无明显发热
- [ ] 喇叭与麦克风有距离、无啸叫

## 10. 常见坑

- 功放 **SD 悬空 → 静音**；
- 麦克风/功放**未共地 → 采集全零或杂音**；
- WS2812 **DIN/DOUT 接反 → 不亮**；
- 5V 供电不足 → 灯环闪烁 / 功放失真；
- 按钮接在 GPIO9（板上 BOOT 键）会冲突，务必用 **GPIO1**；
- ESP32-C3 只有 1 个 I2S0，录音/播放切换要 `i2s_driver_uninstall` 后重装，否则驱动报错。

---

## 11. 需要你确认/与软件配合的事

- 你手上的 **ESP32-C3 具体板型**（是否为 DevKitM-1），GPIO 是否与第 2 节一致；
- 现场 Wi-Fi 与**电脑固定 IP**（写进固件 `SERVER_URL`）；
- 电脑防火墙是否放行 **TCP 8765**；
- TTS 实际 WAV 的采样率/声道/位深，联调时用真实文件核对（协议明确要求，不能只信库默认值）；
- 硬件改动（GPIO/接线/接口）请在 Issue/PR 说明，并同步更新 `docs/接线方案与端口定义.md` 与 `docs/软件接口协议.md`。
