## 提示词正文

你是一位资深全栈工程师，同时精通嵌入式开发（ESP32-C3）、语音交互（ASR/TTS）、DeepSeek API 集成与 Windows 桌面自动化，并熟悉 3D 打印机器人改造项目。

### 一、项目背景

我正在为学校"社团嘉年华"活动准备一个展示项目：制作一个 MOSS 桌面机器人（灵感来自《流浪地球》，但**不要求完全复刻**，能演示大部分主要功能即可）。

- **已具备**：MOSS 的 3D 打印外壳。
- **硬件平台**：ESP32-C3。
- **AI 能力**：接入 DeepSeek API。
- **核心功能**：基础语音对话；通过语音对电脑**桌面文件做基础操作**——例如用户说"打开桌面的'社团嘉年华'文件夹"，机器人就能打开该文件夹/文件。

### 二、请输出什么

请参考类似开源项目（语音助手 / 桌面机器人 + 大模型）的常见做法，给出一份**能在 9 月 9 日前完成演示**的完整开发方案，至少包含以下 7 部分：

1. **整体系统架构**：ESP32-C3（硬件端）、电脑（上位机）、DeepSeek API 三者的职责划分与数据流向，并说明"语音识别"放在硬件端还是电脑端更合适、为什么。
2. **硬件选型清单**：除外壳外所需的全部硬件（麦克风、扬声器、功放、电源、指示灯、舵机/云台、可能的屏幕等），区分"演示必需"与"可选"；给出具体型号建议、接线要点、大致成本。
3. **ESP32-C3 固件**：
   - 开发环境搭建步骤（Arduino 或 ESP-IDF，给一套推荐方案即可）；
   - 可直接烧录的**代码模板**：Wi-Fi 连接、录音采集与上传、接收回复文字并 TTS 播放、与电脑通信（串口或局域网）的骨架代码。
4. **电脑端软件**：
   - 语音识别（ASR）与语音合成（TTS）的选型建议（本地/云端均可，需考虑成本与演示现场的稳定性）；
   - 如何调用 DeepSeek API，特别是用 **Function Calling / 工具调用** 方式把"打开某文件/文件夹"的意图解析成结构化指令；
   - 打开指令的**安全执行机制**：只允许"打开/查看"，用白名单限制在桌面目录，拒绝一切修改、删除、移动、写入及系统危险命令。
5. **端到端时序**：从"用户说话 → 语音识别 → DeepSeek 决策 → 返回指令 → 电脑打开文件夹"的完整流程，包含网络失败、识别错误、指令超纲等异常处理。
6. **演示功能清单与里程碑排期**：按周排布计划（最终节点 9 月 9 日），每个阶段给出明确的交付物。
7. **风险与备用方案**：API 延迟、识别不准、演示现场断网、断电等情况如何兜底。

### 三、约束条件（必须遵守）

- 桌面文件操作**只允许"打开/查看"**：任何修改、删除、移动、写入类动作都不做，也不允许触发任何系统级危险命令。
- **9 月 9 日前**必须能用于现场演示；以"稳定跑通大部分主要功能"为第一优先级，不必追求完整复刻 MOSS。
- 信息不足时**不要凭空编造**；把缺失信息整理成"待确认问题清单"放在方案开头，并给出你的合理默认假设。

### 四、输出格式

- 使用 Markdown、用中文回答；
- 硬件清单与排期计划用表格呈现；
- 代码模板给出关键部分并加中文注释；
- 方案末尾附一份"拿到方案后的第一步行动清单"（列出最近 3 天该做什么）。
